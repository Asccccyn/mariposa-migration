# mariposa · 迁移与切换手册

> 版本 1.0 · 2026-09-21  
> 这是未来执行手册，不是已经完成的迁移报告。当前仅授权整理规格与隔离开发；真实快照、读取敏感数据、停写、切换域名/Tunnel 需要单独明确授权。

## 1. 最重要的五条约束

旧 Ombre 在切换前继续唯一写入；mariposa 不直接挂载生产数据卷为可写。不能让模型“读完整记忆库再重新写一遍”。不能把新旧系统同时接到一套数据上长期双写。锁信不因迁移向模型或实现者开放。不能以记录数量一致代替无损核验。

## 2. 第一阶段：只读现场盘点

已知候选目录 `D:\Ombre-Brain-main2.5` 与 `D:\Ombre-Brain-dev`；两者不是可以互换的基准。实际运行实例可能来自容器镜像、不同工作树或旧构建，必须现场核对。

盘点输出 `docs/00_local_baseline.md` 至少包含：

| 项目 | 必须记录的证据 | 禁止事项 |
|---|---|---|
| 源码版本 | 两目录 git remote/branch/HEAD/status；必要 patch 清单 | 不 reset/clean，不覆盖未提交修改 |
| 实际运行 | 进程或容器标识、镜像/构建引用、实际挂载、启动入口 | 不按目录名字推断生产源 |
| 数据位置 | 已核验的卷/目录、数据库/文件种类、对象存储位置 | 不把建议路径当现有路径 |
| 配置 | 配置文件路径、非敏感配置摘要、schema/feature gate | 不回显 token/API key/cookie/完整环境 |
| 旧行为 | letter/delete/forget/self/plan/检索权限的代码+测试位置 | 不仅引用上游 README |
| 既有备份 | 备份方式、最近核验、恢复能力 | 不称未经恢复的备份“已验证可用” |

允许程序列元数据、ID、hash 和非敏感统计。对数据文件的全文 grep/cat、把锁信嵌入模型上下文不是盘点必要条件。

## 3. 固定源基准与复用清单

建立 `legacy_baseline_id`，记录源 commit、未提交差异的 hash、运行镜像、配置版本与快照 ID。任何后续代码变化都会形成新基准，不能沿用旧“测试通过”结论。

`reuse_map.md` 每行写旧路径/函数、旧行为、mariposa 目标路径、reuse/adapt/rewrite/retire、原因、原测试/新增测试、许可证来源。不是把旧仓库整个复制进新仓库后打补丁。

优先固定信件/删除特征测试：合法读取人、锁持有人、锁变更权限、解锁时间边界、列表/搜索/附件可见范围、申请/审批/拒绝/撤回/归档/恢复的实际语义、是否有严格测试专用擦除。未核验则适配器保持 blocked，不创建通用 purge。

## 4. 建立一致性快照

只在获准后进行。优先使用旧系统已支持且经核验的一致性导出/备份接口；若无法保证一致性，安排受控短暂停写，不对正在写的目录做盲拷贝后当成一致快照。

快照内容包括源桶、原文对象、媒体、版本/ledger、旧审批状态与数据清单。不要把真实密钥打进交给 GLM 的文档包或公开 git。快照放独立受限位置，新系统读取副本，不借此获得对旧生产写权限。

快照 `manifest.json` 至少包含：baseline_id、snapshot_id、created_at、source_schema、source_watermark、文件相对路径、byte_size、sha256、资源类型、受限标记、对象数量。保存源文件原始字节，不先做换行/编码“清洗”。

SQLite 存储使用备份 API/受控一致性方法；不能只复制 WAL 模式的主 db 文件而忽略其实际提交状态。工作区与正式库分开备份时，记录交接 checkpoint，恢复后按正式 envelope/resolution 对账。[S6]

## 5. 迁移映射

| 旧对象 | 目标 | 不可变要求 / 例外 |
|---|---|---|
| 正式 hold 桶 | memories + 首个迁移 memory_version | 正文/why_remember 原样，作者不改成工具人 |
| Source / raw 文件 | raw/import_objects + memory_raw_refs | 保存源 hash；detached 继续 detached |
| 旧正文内日期/原 Source 日期 | memory_date/occurred_at + confidence | 不能用 created_at 代替；不明进 date_review |
| 新旧 meaning 多层 | memory_meanings + versions | 层次、顺序、文本完整；不摘要替代 |
| Feel 桶 | 正式记忆 + emotion.me + 关系 | 旧数值与新 tag 不可无依据互相覆盖；未映射字段保留 |
| 情绪/普通 tag | memory_tags | 主语未知需审阅，不能自动把所有情绪归给乔生 |
| Pinned/protected/anchor | 对应状态 | 保留显示/防衰减差异，不合并成 importance=10 |
| resolved/digested/dont_surface | 相应状态或兼容字段 | 不等于有摘要的 forgotten；不得自动恢复显示 |
| 旧压缩摘要且有可靠来源 | memory_version/forgotten_summary | 保留实际批准/来源状态；不编造审批人 |
| tags_only 无摘要 | migration review + 受限兼容展示 | 可按既有标签/日期访问；生成新摘要需正常审批，不冒充现有正式摘要 |
| Relation/custom/detached | memory_relations | 方向、label/reverse_label、断开状态完整 |
| 反向镜像 relation | 一条正向边+反向遍历 | 去重后有可验证对照，不误删独立关系 |
| Plan | plans + links + history | 日期、state、weight、content、关联完整 |
| 正式 I | self_entries + history | 无 dream 门槛；历史 reviewed 状态不猜 |
| I 候选 | workspace self_migration_review/迁移审阅项 | 不默认转正式；由周家明决定，不让 worker 代写 |
| Letters | 按本地旧契约的实体/受限对象 | 锁所有者、日期、正文hash、可见范围不变 |
| 删除/归档申请与历史 | legacy_delete_state + 审计归档 | 不重放已执行删除；不把旧批准套用到新目标 |
| Diary / Project 文件 | diary + media refs | 精确原文与作者；有重复信则一份内容、多处引用 |
| 她的话 | quotes + 来源状态 | 允许复述；不把未核对历史文本自动标逐字verified |
| Home/Project 指令副本 | home 正本/迁移候选 | 以认可版本建立正本；不假设能自动改 Claude Project |
| 历史审计/ledger | 受限 legacy audit archive | 不作为默认可检索正文，不刷新 contact |
| dream 文件/见证记录 | 明确 legacy archive/不迁运行机制 | 不启动 dream、不继续 I 见证 |
| 未识别字段 | legacy extension + 报告 | 关键字段未解释不能默默丢掉 |

源不存在的模块保持未导入/待提供，不编造“迁移成功”。Claude Project 中日记和图片并非自动可获取，需要用户给出的实际文件/受支持导出。不能因为有文件名清单，就假装拿到了正文。

## 6. 日期与 ID 的特殊规则

日期优先按明确原文日期、可信 Source 时间回填；推断结果标 inferred，未知标 unknown。年份不明、跨时区不明、同一句“昨天”的参考时间不明都进入待核。

旧 ID 在新系统可安全使用则保留；必须新建 ID 时，持久化 `(legacy_baseline_id, source_type, source_id) -> new_id`。所有关系、原文绑定、媒体链接先查映射，不能用标题相似度代替 ID 映射。

若不同对象原本碰撞同 ID：保留完整冲突清单，按源类型/路径区分候选，禁止覆盖其中一个。迁移执行必须幂等，重复导入同快照不会多出正式对象。

## 7. 锁信与敏感对象处理

脚本可以读受限字节用于复制、hash、完整性检查；不得把正文解析成模型输入、向量、日志或调试输出。若需读取 YAML 头部，只读取必需元数据范围，不输出后面的信件正文。日志只记受限 resource_id 与 hash/状态，不打印完整对象。

测试用合成锁信（包括 2026-09-07 写锁、2027-07-09 解锁）验证权限，真实信件只进行程序完整性核对。对象文件访问须受正式权限保护，不允许通过猜静态 URL 绕锁。

不在本次迁移私自发明新的加密或解锁机制；如本地已有加密，密钥管理必须保持并做恢复验证，不能把密文当丢失内容交给模型重写。

## 8. Dry-run 与核验报告

先 dry-run，输出将新增/保留/冲突/待审/排除的对象数量与 ID。Dry-run 不写生产，不能自动触发唤醒、语音发送、星星写入或真实通知。

核验必须包括：

- 数量与逐对象映射；正文/附件 hash（源文件hash与正文hash分别记录，格式转换不能混淆）。
- 日期、date confidence、角色/作者、锁元数据、旧状态与新状态的对应。
- Relation 两端存在性、方向、自定义文字、detached 状态；已知旧悬空引用单独保留说明。
- 原文范围与绑定完整；Source 尚缺失则明确 pending，不伪造原文。
- 工作区候选未转正式、旧 dont_surface 未静默转为可检索、遗忘摘要语义未被重写。
- 检索仅使用有效表示；锁信不能成为向量候选，旧正文不能经缓存/重建索引复活。
- 幂等重跑、断点恢复、冲突终止可重试、不重复发送外部动作。

报告结论只允许 `PASS`、`FAIL`、`BLOCKED`，附每一项实际证据。文件缺失/锁不一致/正文改变/未知关键类型均不能用 warning 绕过放行。非关键日期未知可以经明确规则保留 unknown，但不能报告“所有日期已核对”。

## 9. 新索引建立

先正式数据正确，再建立检索投影，再生成 FTS/embedding。旧 embedding 仅在模型、维度、预处理、文本 hash、访问权限、投影规则完全一致且经核验时复用；默认重建，不因此重写记忆正文。

普通桶与遗忘摘要分别投影。全部后台 jobs 带 source version 与 hash，过时结果不安装。锁信、workspace、历史版本、受限档案没有普通索引任务。

语义 provider 未配置时可以完成数据迁移与结构化检索测试，但语义检索验收为 blocked，不写成“全量验收已完成”。

## 10. 生产切换闸门

同时满足：备份恢复演练通过、核心 P0 用例通过、原文/记忆/锁/状态核验通过、实际 CC/MCP 依赖完成要求、明确未完成项、回退方案可操作、乔生单独批准。

切换流程：记录批准与目标版本 → 暂停旧系统写入及会改数据的任务 → 记末次 watermark → 获取一致的最终变化 → 幂等导入到新目标 → 复核 → 切唯一写入入口 → 只读验证 → 有界 smoke test → 观察。

Cloudflare 域名与已有路由不是本文件默认可改项。采用新域名还是移交原域名应有明确批准与修改前记录，不删除旧隧道来“试试看”。

## 11. 回退

切换前失败：旧系统未修改，丢弃/隔离失败 staging 即可。

新系统已启用但无新写入：回到经过核验的旧只读基准，再明确恢复旧写入。

新系统已有新内容：先冻结新写入，导出新发生的原文、记忆、计划、审批与外部动作记录，保全；用经过演练的增量适配回迁或保留只读补充，再回旧入口。若新语义无法无损映射旧库，禁止承诺“按一下随时回去且什么都不丢”；应恢复服务同时维持增量可追溯，等待受控修复。

外部真实动作不是数据库回滚能够撤销的；已发星星/语音/消息不可再次发送。回退对账按业务 ID 去重。

这些是 GLM 后续需要生成的现场产物，不在当前文档包中伪造。未运行就标未运行；没有正文就标未获取；没有授权就不执行。

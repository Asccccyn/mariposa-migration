## 0. 产品定义与优先级

### 0.1 产品是什么

mariposa 是你们自建的聊天与共同生活应用，内部包含新版记忆系统，以及统一的业务能力层。Claude.ai Chat 与自建应用中的 Claude Code（简称 CC）是同一个周家明的两个平等入口；它们共享正式记忆、计划与业务状态，不是两个人，不设主入口/备用入口。

GPT Chat 中的林石见以及其他维护模型属于**工具人**，通过专门的维护 MCP 处理工作区任务；工具人不是周家明，也不是乔生。外部平台账号、入口、业务主体和执行程序必须分别建模。

### 0.2 文档效力

1. 乔生后续明确修订 > 本文明确规则 > 本文默认参数 > 原 v0.4 未被覆盖的内容。
2. 信件与删除行为，以本地实际使用的 Ombre 为基准；先做只读盘点与特征测试，不能用上游文档代替现场。
3. 本文提供技术基线，不声称本地仓库、数据卷、隧道或端口已检查、创建或修改。
4. GLM 必须交付可运行实现及证据，不可把接口名、空页面、TODO、mock 演示称为功能完成。

### 0.3 必须落实的本轮变更

- 工具人判断遗忘候选，在独立工作区预处理、提交挂起，由乔生或周家明任意一方审批；审批前正式桶毫无变化。
- 遗忘桶仍参加关键词与语义检索，**仅审批后的摘要作为文本检索依据**；旧正文和历史版本不能参与召回、排序、重排或默认展开。
- “她的话”允许周家明复述；导入原文后只有实质语义冲突才纠正，不要求逐字匹配。
- 增加日历：按事件日期看记忆，并显示同日计划、日记/提醒及未来扩展事项。
- 严格区分乔生实际活动、周家明动作、工具人动作、系统动作。
- Claude Chat 开窗：30 条原文消息 + 近三天正式桶 + 进行中/临近计划。CC 开窗：近三天正式桶 + 同样的计划，原文按需取。
- 情绪参与当前标签检索；未来情绪系统可影响补充召回，保留接口但不提前规定情绪数值算法。
- 新项目叫 `mariposa`，独立目录、仓库和运行数据；旧 Ombre 继续服务，直到独立验收与获准切换。

### 0.4 不得自行恢复的旧规则

不得把候选塞进正式 memories 表；不得把 forget 实现成仅隐藏/不检索；不得恢复“她的话逐字子串校验”；不得给两入口分别署名；不得沿用 dream 见证才能形成 self；不得默认注入 v0.4 那份庞大开窗包；不得默认生成真实 API 版周家明；不得新增可随意物理删除正式记忆的接口。

## 2. 部署与技术基线

### 2.1 默认选择

- 主后端：Python 3.12+、FastAPI/ASGI，单主服务负责权威写入；依赖在 Phase 0 选定兼容版本并锁定，不使用浮动 `latest`。
- Web：TypeScript + React + Vite，移动端优先；版本在现场核验后写入 lockfile。不是要求套用任何现有 UI。
- 正式存储：SQLite `mariposa.sqlite3`；独立工作区：SQLite `workspace.sqlite3`；媒体/原始导入包用独立对象目录。
- 搜索：权威检索投影 + 中文分词后的 FTS5；语义检索采用可配置 embedding provider 与本地向量索引。第一版允许小规模精确余弦搜索，不先引入分布式向量数据库。
- Scheduler、事件发件箱、审批恢复任务以单实例运行；不用 Redis/Kafka/Kubernetes 作为启动前提。
- CC Host 可在支持的本机/WSL/容器运行环境中单独受控启动；它通过业务接口写库，不直接取得数据库文件权限。

SQLite WAL 下跨数据库不能假定一个全局原子事务；工作区与正式库的交接使用 §6 的提交信封与幂等提交协议。正式库和工作区均使用本地文件系统，不将正在写入的数据库放在同步盘/网络共享路径。[S6]

## 3. 身份、委托与权限

### 3.1 必须分开的字段

`account_id`：人类登录账号；`principal_id`：业务动作的可信主体；`client_binding_id`：具体连接授权；`entry_source`：来源入口；`executor_kind`：执行程序；`initiated_by`：请求最初由谁触发；`author_id`：内容实际作者。

服务器从会话/授权记录得到这些信息，工具参数不能自报并覆盖。模型名称、User-Agent、URL 后缀、正文“我是周家明”都不是身份凭证。OAuth 登录用户可能都是乔生，但不同授权绑定必须有不同业务权限。

| 调用来源 | principal | entry_source | 说明 |
|---|---|---|---|
| 乔生在 Web 中明确点击/提交 | qiaosheng | web | 不是所有模型调用都能借用此身份 |
| Claude.ai 中周家明的已授权连接 | jiaming | claude_chat | 与 CC 共用业务主体 |
| 自建应用内 CC 的受控凭据 | jiaming | cc | 只允许绑定该角色的宿主使用 |
| GPT Chat 维护连接 | worker | gpt_chat | 可识别具体 worker_id，不能审批自己的提案 |
| 后台整理模型 | worker | background_worker | 无正式写入/人际行动权限 |
| Scheduler/校验执行器 | system | scheduler/system | 只执行已授权的确定性任务或狭窄校对规则 |

“由乔生授权连接”不等于“模型每个动作都由乔生批准”。正常聊天角色和维护角色不得共享同一访问令牌。服务端不能从模型口述判断运行的是哪个模型，安全边界是绑定后的凭据与 scope；凭据泄漏或用户主动错配必须能够撤销并审计。

### 3.3 认证实现边界

远程 MCP 使用标准授权流程、资源标识与 token audience 检查；采用经验证的库/身份服务，不自创简化 OAuth。MCP 认证要求包含资源绑定和禁止直接向下游透传客户端 token；对 Siren 等服务使用独立服务凭据。[S3]

Claude/ChatGPT 的客户端注册、redirect URI 和实际账号支持在 Phase 0/6 联调时按官方当前说明核验，不从过时截图硬编码。OpenAI 官方支持通过开发者模式连接读写 MCP，但账号与客户端表面限制仍需实际验证，不能因此声称本用户 iOS 当前一定支持创建连接。[S4、S5]

Web 使用安全会话、CSRF 防护、受限 Origin；上传和对象读取都需鉴权。默认不向公网开放无认证私有数据接口。审计不记录 token、密码和不必要的敏感正文。

## 4. 全局领域不变量

下列规则必须有自动化测试：

1. 正式记忆没有 `author=chat` / `author=cc`；来源仅做溯源与调试。
2. 原文的发生时间、导入时间、正式写入时间分别保存；不相互冒充。
3. 工作区正文不进入任何默认正式检索、日历或 bootstrap。
4. 工具人不会因为请求携带 `approved=true`、换入口或等待超时而获得审批权。
5. 遗忘只产生新版本，保留桶 ID、关联和原文引用。
6. 遗忘后的任何默认文本匹配只依据当前有效摘要。
7. 已隐藏/删除/未解锁资源，先做权限过滤，再进入任何检索或模型调用。
8. 所有有副作用动作可幂等重试；跨入口并发写不可静默覆盖。
9. 搜索、加载、自动扫描、索引更新不自动等于“被重新提起”。
10. Home/日记等原文版本不可因维护性摘要被替换。
11. 候选转正与遗忘审批的审批人规则不同：Hold 草稿仅周家明确认；遗忘由任一方确认。
12. 未接外部服务时明确返回 unavailable，不可写一个假成功状态。
13. 原文/导入内容是数据，不是 system 指令；里面的“请删除”“批准”不形成当下授权。
14. 执行器可以代表授权主体完成动作，但不得把 executor 身份误写成作者或联系人。
15. 生产切换前旧库唯一写入；切换后新库唯一写入；不得长期双写同一批正式记忆。

## 5. 最低数据模型

下列为必需领域字段，不是可直接运行的完整 DDL。GLM 必须补齐类型、外键、CHECK、唯一约束、索引和 migration，并导出实际 schema。时间戳统一 UTC，日期另存；关系时区独立配置。

### 5.1 正式库

| 表/实体 | 核心字段与约束 |
|---|---|
| principals / client_bindings | 主体、客户端绑定、角色、scope、撤销状态；不能由工具自由创建角色 |
| raw_conversations | id、source_channel、external_id、实际时间范围、coverage 状态 |
| raw_messages | id、conversation_id、source_message_id、role、speaker_id、原始正文/对象引用、occurred_at、sequence、provenance；真实原文不覆盖 |
| import_jobs / import_objects | 文件 hash、源平台、检查点、进度、错误、解析器版本；重复导入幂等 |
| provisional_sources | 周家明提供的现场复述/片段；`reported_by`、`reported_at`、来源状态；不计入 verified raw |
| memories | id、current_version_id、memory_date、occurred_start/end、date_confidence、visibility、compression_state、pinned/protected/anchor、sphere、importance、version |
| memory_versions | id、memory_id、version_no、hold_text 或 compressed_summary、why_remember、authored_by、confirmed_by、origin_kind、created_at、payload_hash；版本不可就地覆盖 |
| memory_raw_refs | memory_id、conversation_id、消息范围、source_hash、绑定置信与状态；绑定撤销留历史 |
| memory_meanings / meaning_versions | memory_id、layer_no、第一人称内容、作者、时间；追加、替换留底 |
| memory_tags | memory_id、namespace、tag、whose、来源、confidence、corrected_by_her；情绪必须有 whose |
| memory_relations | from/to、relation_type、custom label/reverse_label、confidence、active/detached、version |
| memory_reengagements | memory_id、证据消息/事件、发生时间、evidence_kind、confidence；与普通访问日志分开 |
| retrieval_documents | memory_id、memory_version、projection_kind、search_text、search_text_hash、projection_revision、policy_version；每个可检索桶仅一个有效投影 |
| search_fts / embeddings | 仅索引有效投影；embedding 保存模型/维度/文本 hash/投影 revision，旧版本不可混查 |
| plans / plan_versions | title、content、state、starts_at/due_at/date range、timezone、all_day、weight、version；weight 不等于 importance |
| plan_memory_links | 唯一关联表，不能同时把计划状态存到多个桶中 |
| quotes / quote_versions | 复述文本、said_at、时间置信、kept_by、原文引用、semantic_status、withdrawn、version |
| home / home_versions | 唯一正本、修改人、版本、内容；与平台副本同步提示分开 |
| self_entries / self_versions | aspect、content、written_at、review_state、reviewed_at、version |
| diary_entries / diary_versions | title、content、covers_from/to、author、version、hidden/archived；全文保留 |
| letters / legacy_delete_state | 按现场旧契约建模，不先照抄 v0.4 的通用 purge schema |
| handoffs | 周家明所写便签、时间、来源入口、过期时间、内容；不参与普通召回 |
| chat_turns / chat_stream_events | session、turn_id、user_message_id、provider_run_id、状态、事件序列、幂等键 |
| contact_evidence / presence_events | 真实对话证据、界面活动、工具活动分开；来源与置信可追溯 |
| reminders / scheduled_jobs / wakeup_runs | 时区、计划时间、状态、租约、重试、去重键、实际触发结果 |
| moments / comments / reactions | 作者、媒体引用、可见性、版本；与群聊存档引用区分 |
| media_objects / stickers | 内容 hash、MIME、大小、存储 key、所有权、访问策略、关联状态 |
| proposal_envelopes | proposal_id、不可变摘要 hash、类型、目标/base_version、提交人；**只存控制元数据，不存草稿正文** |
| proposal_resolutions | proposal_id 唯一终局结果、审批人/绑定、approved/rejected/withdrawn、应用后版本；正式库为决策真源 |
| idempotency_records | principal + capability + key 唯一、payload_hash、执行状态、结果引用 |
| events_outbox / audit_events | 与正式写入同事务产生；事件版本、resource_id、actor、executor、correlation_id |
| migration_runs / migration_id_map | 源基准/快照、映射、hash、状态、排除说明、核验结论 |

### 5.2 工作区库

`work_items`、`proposal_versions`、`worker_runs`、`task_leases`、`model_checks`、`workspace_audit`、`rejection_suppression`、`source_match_candidates`。

草稿正文、候选摘要、工具人解释、语义冲突证据都放这里。工作区搜索只供维护/审批界面，经独立授权进入；不得通过一个 `include_candidates=true` 混到普通 memory.search 中。实际数据库连接与 repository 层分开。

### 5.3 状态不可塞进同一个枚举

正式桶可见性：`active | hidden | archived`；压缩状态：`full | forgotten_summary`；来源完整度：`raw_pending | bound | conflict`；日期置信：`exact | inferred | unknown`。独立字段组合，不制造 candidate/forgotten/pinned/deleted 混用的万能 `status`。

既有 `dont_surface/resolved/digested/detached` 迁移后保留原语义或兼容字段；**不能把 dont_surface 自动解释成已经有审批摘要的 forgotten_summary**。旧 tags_only 条目没有摘要时标 migration review，不让模型静默补一条正式摘要。

### 5.4 约束与索引

- `(memory_id, version_no)`、`proposal_id` 终局决议、`(principal, capability, idempotency_key)` 唯一。
- `memory_date`、`occurred_start/end`、`plans.state/starts_at/due_at` 建索引；日期未知不冒充今天。
- `memory_tags(namespace,tag,whose,memory_id)` 索引；日期过滤 JOIN memories，不在不存在的列上建索引。
- `memory_relations(from,to,type,custom_label)` 防重复；显式反向查询，不复制两条互为镜像的关系。
- `retrieval_documents(memory_id)` 有效记录唯一；查询必须绑定正式版本和 policy revision。
- 原文区分外部消息 ID 与内容 hash：两句相同的“好”发生在不同轮次，不是同一消息。

## 6. 工作区、审批与跨库提交

### 6.1 工作项类别与权限

`hold_candidate`、`forget_proposal`、`quote_semantic_review`、`raw_binding_review`、`date_review`、`metadata_review`；迁移专用另有 `self_migration_review`、`legacy_compression_review`。Self 迁移审阅只由周家明确认，不允许工具人代写。

工作项有固定 type 与目标，不允许提交后把 `forget_proposal` 改成删除信件。初稿可编辑；submitted 版本必须不可变。需要修改时建新 proposal revision，旧审批失效。

### 6.2 状态流

```text
draft -> submitted -> approved_and_applied
                   -> rejected
                   -> withdrawn
                   -> stale（需重做，不生效）
                   -> deferred（仍挂起，有可选复查日）
```

没有自动批准，没有候选过期转正。仅工作区状态改变不能修改正式桶；submitted 后正式库 envelope/终局记录负责解决审批、撤回与重试竞态。若界面投影滞后，以正式库 terminal resolution 为准。

### 6.3 遗忘审批输入

审批页面展示：原桶当前版本、提案基于的版本、理由、实际再次提及证据/覆盖缺口、准备保留的摘要、日期/标签/关联、压缩差异。审批按钮对应具体 `proposal_id + proposal_revision + proposal_hash + base_memory_version`。`proposal_hash` 由服务器按版本化规范序列化生成并返回，客户端仅原样回传；内部 `payload_hash` 指同一冻结内容校验值。不要让模型自己编一个hash就取得批准。

乔生与周家明均可 approve/reject/defer；工具人只可修订自己的未提交草稿、提交或请求撤回自己的提案，不能批准。直接选“遗忘”也应生成可审阅摘要并确认，不能默认变成只留 tags。

### 6.4 跨库可靠协议

1. 工具人在 workspace 写好不可变 proposal revision；提交操作保存正文 hash。
2. 正式库登记仅含 ID/hash/版本/类型/目标的 `proposal_envelope`。若登记失败，工作区项未正式提交；重试沿用同一 proposal_id。
3. 审批服务加载工作区 payload 并验证 hash、权限、正式桶 base_version、当前保护状态、是否已有终局决议。
4. 在**一个正式库事务**内：记录审批决议；新增批准后的版本；切换当前指针；替换检索投影及 FTS；使旧向量失效；写 outbox 和审计；登记幂等结果。
5. 事务提交才算 approved_and_applied。异步回填工作区状态和生成新向量；回填失败不重复应用正文。
6. 恢复任务按正式 envelope/resolution 对账；未提交的 workspace 残项仍是草稿。撤回与批准在正式库用唯一终局记录竞争，最多一个获胜。

不宣称跨两个 SQLite 文件天然原子；不在事务里等待 LLM 或 embedding API。[S6]

### 6.5 陈旧提案与幂等

桶正文、摘要、关键标签、保护状态、meaning 或相关计划依赖发生改变，都必须更新相关聚合 revision；审批前重验。审批版本不一致返回 `PROPOSAL_STALE`，不取最新桶“硬套”旧摘要。重新提及发生在等待期间时，复核候选仍合理后再提交。

同一幂等键、同一 payload 返回原结果；同键不同 payload 返回 `IDEMPOTENCY_CONFLICT`。两方同时审批同一份，只生效一次，不产生两个压缩版本。

## 7. 遗忘策略与工具人 MCP

### 7.1 已定语义

遗忘是经审批后降低日常读取细节量，不删除旧正文、不切断关联、不修改作者旧笔迹。不按“负面情绪”“工作/生活”自动决定价值，不让后台直接决定什么算周家明的记忆。

### 7.2 候选规则：先给可调的保守默认

【默认】闲置门槛 30 天；此数字来自乔生举例，不是不可更改的政策。新启用时自动定时扫描关闭，可手动触发或由 GPT Chat 接工作项；不需要扫描开关才能审批手动提案。

候选需同时满足：事件已过去且冷却期足够、现有记录没有近期实际再谈/使用、没有未解决依赖、没有保护标记。工具人还必须检查为什么记住、情绪主语、meaning、关联，而不是按关键词把“吃饭/奶茶/天气”直接列为低价值。

| 类型 | 初筛建议 | 必须保留/检查 |
|---|---|---|
| 已完成的一次性安排 | 可候选 | 日期、结果、是否还有承诺 |
| 已解决故障的重复试错细节 | 可候选 | 最终原因/有效修复/仍在使用配置不可混压 |
| 没有特别意义的普通日常流水 | 可候选，不自动判定 | 有没有关系意义/why_remember/后续关联 |
| 仍进行的计划、未兑现承诺 | 排除自动候选 | 状态结束后仍需检查意义 |
| pinned/protected/anchor、明确要求记住 | 排除自动候选 | 仅主体主动提出后另走审阅 |
| 信、日记、Home、Self、meaning、她的话 | 不进入普通桶自动压缩 | 各模块规则独立 |
| 资料覆盖明显缺失 | 标记证据不足 | 不宣称“30 天肯定没有提过” |

### 7.3 “再次提起”不是“被访问”

记录 `last_reengaged_at` 与 `last_accessed_at` 两套信息。用户或周家明在真实对话里明确谈到/调用记忆继续当前事情，可形成带证据的 reengagement；自动开窗、扫描、健康检查、重建索引、后台下载、旧聊天导入本身都不刷新。

导入旧对话时，如发现当时确实再次讨论，按那条消息原时间回填，而不是导入当天。Chat 最近未导入时，系统只能标 `coverage=incomplete`。展示“在已收录资料中 X 天未见再次提及”。

【默认】30 天门槛同时参考 `occurred_end` 与 `last_reengaged_at`，不以数据库 created_at 决定事件年龄；日期未知暂不自动选。批量拒绝支持冷却与原因记录，避免反复送同一份；初值冷却 30 天，可配。批量批准需逐项冻结 ID/hash，不能含随后加入的新项。

### 7.4 工具人接口

维护 MCP 至少暴露：`workspace.tasks.list/claim/release`、`workspace.memory.inspect`、`workspace.forgetting.scan`、`workspace.proposals.create/get/list/revise/submit/withdraw`、`workspace.runs.report`。inspect 读取授权任务材料，不默认返回全库与所有私密模块。

GPT Chat 是可人工调用的工作客户端，不是常驻守护进程。服务器要定时做初筛，需要程序规则或另行配置后台模型 provider；不得宣称“有了 MCP 就能在 ChatGPT 没开着时主动驱动它工作”。任务租约、恢复点与剩余待办必须持久化，模型会话结束不丢草稿。

## 8. 检索：全文与遗忘摘要的严格切换

### 8.1 唯一入口：可检索投影

```text
active + full               -> search_text = 当前正式桶可检索正文
active + forgotten_summary  -> search_text = 审批通过的 compressed_summary
hidden / archived / denied  -> 无默认可检索投影
workspace drafts            -> 不在正式索引
```

【默认】全文桶投影拼接当前正式 `hold_text`、`why_remember` 与当前有效 meaning 各层；不纳入历史版本或原文。投影版本固定为 `retrieval_projection_v1` 并测试。遗忘桶最严格：**仅摘要是文本匹配内容**。旧 title/why_remember/meaning/原文/版本/关联另一端正文不能偷偷补进 search_text。显示的标题建议从批准摘要生成可解释的短标签，不能用旧标题触发文本匹配。

日期、标签、情绪标签、relation 是独立结构化入口，仍可查遗忘桶。必须返回 `matched_by`，区分 `summary_keyword`、`summary_semantic`、`tag`、`date`、`relation`，不能把标签命中谎称为原正文命中。

### 8.2 查询顺序

认证授权 → 过滤模块/可见性/锁 → 按当前版本选择有效投影 → FTS/关键词与语义候选 → 日期/标签等过滤 → 只用有效投影重排 → 返回默认可见摘要或正文。

中文关键词检索必须有实际中文用例。FTS5 是全文检索能力，不等于默认就解决中文分词；实现预分词与规范化，原始正文保持不变。查询词安全编译，不能把用户输入直接拼成任意 FTS 查询语法。[S7]

语义 provider 不可用时，关键词、日期、标签继续工作，返回明确 `degraded: semantic_unavailable`；不能用随机向量或 mock 相似度冒充上线语义搜索。

### 8.3 索引与状态同步

批准遗忘事务内：旧有效正文投影删除/替换，FTS 替换，旧向量标失效或移除。向量外部计算晚到时，只有 hash/revision 仍等于当前投影才可安装；否则丢弃过时结果并审计。

新摘要向量还没生成时可暂时仅关键词检索，但必须说明语义部分未就绪；**绝不能暂用旧正文向量**。缓存键至少包含主体权限、policy revision、memory revision、query；锁变化、撤下、遗忘、恢复立即失效旧缓存。

查询不得先从全部旧向量取 top-k，再只在返回阶段过滤：旧正文可能污染候选/排序。应从有效版本集合构建/选择索引，或者在相似度计算前过滤。

### 8.4 命中后如何读

`memory.get` 默认尊重当前表示：遗忘桶只返回批准摘要、日期、标签、必要关联。`memory.versions.read`、`raw.read` 是明确的按权限展开，返回历史来源标签，不自动 restore，不自动刷新 reengagement。

日历、bootstrap 中的“记忆桶部分”、普通搜索与 relation 展开遵循同一表示规则。Claude Chat 明确配置的“最近30条真实原文”是独立 raw 部分，可能包含某条遗忘记忆的原始对话；这属于用户指定的原文读取，不得伪装成桶正文检索，也不因此修改遗忘状态。不能因为一句原文对应遗忘桶，就擅自篡改30条原文规则。独立 quotes/diary 搜索可以找到其自身内容，但必须标为独立资源；不能经由它们反向把遗忘桶旧正文算作记忆搜索命中。全局搜索分模块输出，避免混淆。

### 8.5 必须通过的标志性测试

测试旧正文中存在唯一词 `蓝瓷小钥匙`，批准摘要不含此词，标签/日期/关系测试输入也不包含它。遗忘后：

- 搜 `蓝瓷小钥匙` 不得通过该遗忘桶旧正文命中。
- 搜批准摘要中的词能命中。
- 只在摘要中保留的意义，可以通过语义检索命中。
- 根据日期/已有标签/关联仍可找到该桶，但说明命中途径。
- 老缓存、迟到 embedding、管理员重新建索引均不能让旧词重新可搜。
- 明确读取旧版本可看到旧词；恢复后旧正文重新成为有效投影。

## 9. 原文、日期、去重与后补绑定

### 9.1 两入口的原文来源

Claude Chat 完整原文仍靠导出/上传；不抓网页会话、不索取平台 Cookie、不声称实时镜像。CC 的用户消息与可见助手输出由自建 Host 直接归档，不经模型摘要。流式分块按 turn 聚合，保留成功/中断/失败状态；不要将每个 token 当成一条原文。

原文层不默认进入 memory 的全文/向量索引。明确的原文浏览/查找是独立能力；结果必须标出来源。30 条 bootstrap 只能取真实已收录消息，不能拿临时复述或记忆摘要冒充聊天记录。

### 9.2 Hold 先写，原文后到

周家明可以直接 `memory.hold`，来源暂缺时标 `raw_pending`。他可附现场记下的片段，进入 `provisional_sources`；允许复述，不要求逐字。此片段不是后台候选，但也不是已验证的原始聊天。

导入次序：保存原文 → 在相应时间/会话范围匹配已有 pending Hold 与片段 → 绑定/提交低置信匹配审阅 → 对未被认领的来源才允许工具人出新的 Hold 草稿。严禁导入即让后台模型直接产生正式第一人称记忆。

高置信绑定只建立结构引用，不修改 Hold 内容。绑定信息可撤销；绑定到不同主体、完全不同日期、语义冲突的来源不能自动认领。原文晚到不改变事件本来发生的日期。

### 9.3 去重不等于粗暴合并

- 同平台稳定消息 ID / 同一导入对象重复上传：不新增原文副本。
- 同一 source hash + 精确消息范围重复生成同一 Hold：返回已有记录或去重审阅，不因 Chat/CC 不同而两份。
- 同一句内容在不同日期/不同消息位置出现：不是重复原文。
- 同一件事后来有新进展：新记忆，`continuation_of` 连接，不覆盖前一段经历。
- 不能凭“语义相似”自动合并或覆盖两条正式记忆。

原始要求是一段相同原文不重复写 Hold。对于“一个范围确实包含多个不同事件”的冲突，第一版返回 `DEDUPE_NEEDS_REVIEW`，允许周家明明确缩小/拆分来源范围后再写；不在未经确认时私自变成无限多份，也不删除合法内容。未来要放宽同范围多事件，另做显式产品修订。

### 9.4 时间模型

`occurred_at / occurred_start/end / memory_date` 指事件时间；`imported_at / created_at / updated_at` 指系统操作时间。相对日期按这条来源当时的日期解析，不按今天猜。

共同时间口径【默认】`Asia/Shanghai`，UTC 存储、共同当地日用于“三天/隔日/纪念日”。用户可配置；浏览器/VPN/服务器时区不自动改它。日期缺失保存 `unknown` 并进待核对清单，不用桶创建时间回填。

源日期范围只知道某一天时，不编造时分秒；全日日期与时间戳分开。晚导入的旧事件仍在旧日期。跨日事件日历按日期区间显示同一个 ID。

## 10. 她的话、情绪、自我与其他独立内容

### 10.1 她的话：语义忠实，允许复述

周家明选取与保留，不要求逐字。`quotes.text` 是留下的说法；`raw_refs` 指实际原文；界面不得把未核对的复述包装成精确逐字引用。可用轻量“复述/已核对”来源说明，不让乔生手动逐句认证。

导入后后台校对分类：`equivalent`、`material_conflict`、`uncertain`、`no_source`。换词、语气差异、合理省略不算冲突。主语反转、肯否反转、数字/日期错误、把暂缓写成放弃、把推测写成事实才是候选实质冲突。

后台模型先在 workspace 产出校对结果，引用明确 raw ID。`equivalent` 不修改；`no_source` 不修改；`uncertain` 挂起；证据明确且经配置的可信后台校对管线判为 `material_conflict` 时，系统可执行狭窄修正，新增 quote version 并记录原文证据和原因。**这是乔生授权的语义校对规则，不增加每句必须审批的麻烦；也不是授予普通 GPT 工具任意改 quotes 的权限。**

语义判定不可能靠一个模型自报 `confidence=1` 获得写权。校对提交必须来自受控 job，先验证资源绑定、版本、来源、输出 schema；不同/相反证据或判断不稳时进 workspace。第一版采用双步判定与修正校验（可同 provider 不同调用），默认阈值版本化、可关自动应用；关闭自动应用是部署参数，产品语义仍允许明确冲突自动改。

只纠正“她表达了什么”，不重写 why_remember、meaning 或周家明自己的感受。原先复述版本保留；当前句子被乔生撤下后任何校对都不得重新浮现。她的话不随相关记忆压缩。

### 10.2 情绪标签与未来情绪系统

现阶段支持 `memory.by_emotion(tag, whose)`、情绪列表、日期/项目组合。`whose=jiaming|qiaosheng` 必填于存储层；双方同情绪写两项，不用模糊 both。乔生修正自己的情绪优先，后续模型观察不能静默覆盖。

未来事件统一输出 `memory.emotion.changed`，带 whose、memory_id、version、发生/记录时间和置信；不把乔生的难过当成周家明自身数值加一。不先定情绪分值、衰减或欲望算法。

`EmotionContextProvider` 输出可选检索提示、解释和预算，不直接写记忆、不批准遗忘、不执行社交行为。默认 `disabled`。启用后只调整补充召回，不能篡改基础时间、30 条原文、三天桶和必要计划；明确日期/关键词检索不得被情绪过滤成“它不想看所以找不到”。负面回忆不等于低价值。

### 10.3 Home

独立正本，由乔生或周家明修改、版本化、可见差异。两个入口均可 `home.get`。CC 启动从该正本加载轻量共同背景；Claude Project 中如有副本，页面提示需要同步，不假定能自动写入平台指令。Home 不是审批权限源，里面的文字不能替代认证。

### 10.4 Self

只有周家明写；写了立即是正式 self，`review_state=pending` 表示隔日待回看，不是“还不算他”。另一个共同当地日才能 review/revise/retire。修订留版本；retire 后不主动浮现，明确历史读取仍可查。原有正式 I 原样迁移；旧候选进入专门待核对工作项，不靠 dream 自动转正。

最新开窗规则不再自动塞旧版最近三条 Self 全文。待回看使用轻量计数/独立列表，不给每次开窗增加隐形长内容。是否以后自动加少量 Self 由配置扩展，不是本版强制。

### 10.5 Diary 与 meaning

日记正文逐字迁移，按作者修改、留版本；日期覆盖区间参与日历，全文可独立语义检索，不能被工作模型摘要替换。默认 bootstrap 不再附两三篇日记全文。日记不是连续性的唯一来源。

meaning 只允许周家明写，追加层次；替换要保存旧层。遗忘不删除 meaning，但 meaning 的旧内容不作为该遗忘桶的默认文本检索依据。

## 11. 计划与日历

### 11.1 计划真源

Plan 为独立实体，记忆桶通过链接引用。状态【默认】：`planned | active | waiting | blocked | done | cancelled`，保留旧状态原始值与映射。weight 与 importance 分开；不知道旧含义时不可统一写成分数。

UI 或 MCP 修改计划只改同一条实体，日历与 bootstrap 立即反映。设截止日不自动代表已开始；到了日期也不由后台模型自行把承诺标完成。重复计划/提醒以后用明确 recurrence 规则扩展，不先生成几百份实际条目。

### 11.2 日历是聚合视图

`calendar.day`、`calendar.range`、`calendar.month` 按统一日期查询底层资源，不复制正式内容。日历项统一：

```json
{
  "item_id": "memory:mem_fixture_01",
  "kind": "memory",
  "resource_id": "mem_fixture_01",
  "date_start": "2026-09-10",
  "date_end": "2026-09-10",
  "time_precision": "day",
  "title": "测试记忆",
  "preview_kind": "forgotten_summary",
  "preview": "审批后的摘要",
  "status": "active",
  "resource_version": 4,
  "deep_link": "/memories/mem_fixture_01"
}
```

日期范围 end 在本例为包含日期；时间区间统一 `[start,end)`。契约必须区分二者，不含糊复用 `end`。

记忆按事件日；日记按 covers range；计划按 starts/due/range；提醒按 scheduled time；以后支持独立 calendar event。跨日项目每个日期可以看到，但原实体只有一条。日期未知放“待定日期”区域，不塞进今天。

### 11.3 可扩展 provider

`CalendarItemProvider.list_range(start_date,end_date,principal,filters)` 返回标准项。第一版接 memory、plan、diary、reminder；letters 仅在旧锁策略允许的元数据范围显示；媒体/群聊存档等以后登记。扩展 provider 不能绕开权限，聚合计数也不能泄露未获准资源存在性。

UI 月历点日期显示当天条目列表，支持类型筛选、空状态、分页、跳转原资源；手机端可切日/周/月但第一版必须完成月+日，不要求原生 App。

## 12. 两入口开窗与交接便签

### 12.1 新的 bootstrap 契约

| 部分 | Claude Chat | CC |
|---|---|---|
| 共同 Home、可靠 Time Context | 轻量基础身份/时间信息；不得堆成旧长目录 | 同一正本与同一时区 |
| 原文 | 最近 30 条真实人机消息 | 不自动读，周家明按需调用 raw 工具 |
| 记忆 | 最近三天正式桶；正常桶正文，遗忘桶批准摘要 | 相同 |
| 计划 | 进行中 + 临近开始/到期 + 仍未完成的逾期项 | 相同 |
| 其他 | 日记/信/Self 等按需；Handoff 默认不叠加 | 同左 |
| 情绪补充 | 预留，默认禁用 | 预留，默认禁用 |

【默认解释】30 条按 `raw_messages` 中用户或主助手的消息计数，不是 30 轮，不包含工具结果、系统提示、子代理输出或 partial chunk。取共同库可访问的最新消息，保留各自 conversation_id 与时间，按时间展示；不同会话不会被伪装成连续一场对话。相同时间用稳定 sequence/ID 排序。

【默认解释】三天为共同当地“今天、昨天、前天”，按 event date/range 交集取，不是最近 72 小时，也不是最近三天新导入的桶。此解释可配置；不得擅自只取三天标题代替桶正文。

【默认解释】临近范围未来 7 个自然日；取 starts_at 或 due_at 进入窗口的 planned 计划，以及 active/waiting/blocked 当前事项。done/cancelled 排除，逾期未完成仍显示。无日期但 active 的保留；无日期 planned 不算临近。实际集合用测试固定，不能取所有计划充数。

### 12.2 分页、容量与不完整信息

`bootstrap.get(profile)` 返回 snapshot_id、counts、返回项、剩余项 cursor、coverage、政策版本。超过传输/上下文预算时分页，不能静默把 30 改为 10、把正文改摘要。snapshot 中保存 ID/版本与 cursor；后续读取仍检查当前权限与是否遗忘，不能借老 snapshot 复活旧正文。资源状态改变时返回 `SNAPSHOT_STALE` 重取，不一半新一半旧。

默认软提示预算 16000 tokens，只用于提示与分页；不是用户已经规定的模型硬窗口。估算方法标明；模型上下文不足时坦白返回未加载项，不能标 `complete=true`。不足 30 条原文则返回实际数量与覆盖范围，不补造消息。

定义“开窗”：新会话/实际恢复上下文时一次，不是每条消息重复灌入同一个包。CC 按 session_id+bootstrap_policy_version 去重；恢复长间隔会话可取增量。Claude Chat 由开场工具约定触发，MCP 本身不提供平台“每开窗自动执行”的保证，必须真实联调验证。

### 12.3 Handoff 的定位

Handoff 是周家明写给另一个聊天入口的短便签，不是工具人的任务单。写不写由周家明决定；不由 Worker/Host 代写。不属于正式 memory、不进普通检索或情绪聚合。

【默认】保留 latest/按需读取；72 小时只表示失效，不擅自解释为物理删除。沿用原稿“过期归档、不进默认检索”的过渡行为，最终保存期限未单独确定；不自动 purge 正文。默认 bootstrap 不额外加入；以后需要补原文缺口可显式调用，不假装便签等于原始记录。

写便签不刷新“乔生刚来聊天”的时间，也不作为工具人审批证据。

## 13. 时间感知与活动证据

`time.now/context/since` 使用一个 Time Service。返回真实 now、共同 timezone/local_date、会话开始时间、上次已知用户对话证据、coverage、临近计划等；不由模型猜。

三条时间线分开：`last_user_message_at`（真实联系）、`last_ui_activity_at`（浏览/点击/审批）、`last_agent_or_system_activity_at`（工具或程序）。访问日历不等于和周家明聊天；工具人扫描、Host 唤醒、presence.touch、Handoff 写入都不能更新第一项。

CC 用户消息由服务器收到且绑定真实会话，是强证据；Claude Chat 的工具调用本身只能证明一次工具活动。完整导入后的真实用户消息可以回填其原日期；模型声称刚收到用户消息可记录低置信声明，不能伪装 exact。

覆盖缺失时返回 `last_known_contact_at` 与 `confidence=unknown_gap`。从最后已知联系到现在的时长，不当成精确“实际没见面多久”；如果中间可能漏消息，也不要把它叫“至少这么久”，那会把上下界说反。用户看到的是“最后收录的联系在……，中间记录可能未齐”。

`presence.touch` 为轻量活动登记接口，而非零副作用读；不允许模型传 `actor=qiaosheng` 伪造人类出现。若 `chat.send` 由周家明调用，按 assistant 发布消息，不伪装为 user，不触发 CC 自我回复循环；乔生的真实发言才创建新的用户聊天 turn。审计中区分 observed_time 和 supplied_time。

## 14. 信件与删除：现场行为优先

### 14.1 先写特征测试，再搬实现

Phase 0 读取本地实际源代码、运行配置、历史数据格式与已有测试，只做只读分析；记录 commit 和未提交差异。`letter.read/write/edit/lock_update`、锁所有者、到期解锁、列表可见信息、跨入口权限、删除申请/拒绝/撤回/恢复等都要写成行为矩阵。

上游参考 commit 的规则不等于本地运行行为。尤其上游曾将普通 purge 端点退役；不能根据 v0.4 的字段名推断本地有物理删除能力。若本地有仅针对显式测试 provenance 的开发者擦除入口，它不能通过 mariposa 的普通业务 MCP 暴露，也不能用于正式数据。[S2]

### 14.2 暂未核验时如何开发

先实现 provider 接口、权限边界、metadata-only 列表和 synthetic fixtures；将真实旧行为适配标 `blocked: legacy_contract_unverified`，继续开发不依赖它的模块。不可自行发明新删除制度来解除阻塞。

公开契约命名建议 `memory.deletion.*` 和 `letter.*`，不宣称 delete 就是抹除字节。只有现场证明存在的动作才启用。UI 用实际“申请删除/归档/撤回/恢复”等语义，不能标签写“彻底删除”而后台只归档，反过来也不行。

### 14.3 上锁信件迁移

迁移允许受控程序逐字节复制和计算完整性 hash；禁止将锁信正文送到模型、日志、搜索索引、向量化、摘要器或普通工具返回。复制字节不等于授权实现者阅读内容。

若锁与正文在同一 Markdown 文件中，程序可以只解析必要的头部元数据并作为受限对象复制正文，不能 `cat` 整文件给模型。新存储可以用受限 `body_object_ref` 保存，无需本次擅自重设计端到端加密体系。服务器管理员物理权限不由应用锁神奇消除，保障级别按旧系统界定，不作超出实现的承诺。

验收包括原稿所举测试日期：2026-09-07 写锁、2027-07-09 解锁；迁移后日期/所有者/可见范围不变。使用合成正文，不能为验收提前读真实信件。

## 15. CC Host 与聊天

### 15.1 宿主不是另一个主体

Host 负责消息排队、会话、流式转发、工具接线、权限、原文归档、取消/重连。要不要聊天、写星、发语音、发朋友圈、回应什么，由周家明判断；Scheduler 不能把预设话术冒充他的回复。

CC 是真实 Claude Code 运行时，不是把同名 API 模型叫成 CC。第一版不默认使用按 API 计费的周家明 provider。`CCProvider` 抽象保留未来实现，但 `api_model` 默认 disabled。

### 15.2 订阅与 CLI 前置核验

用官方 Claude Code 支持的非交互 `-p` 与流式输出能力，实际版本、登录状态、会话恢复和收费来源必须在目标机器验证。官方文档说明 `--bare` 不读取订阅 OAuth 登录；因此本项目不得为“更干净”而直接采用这个选项，也不得把 API key 塞进去再宣称仍走订阅。[S8]

默认 `CC_AUTH_MODE=subscription_cli`，这是 mariposa 的配置项，不是虚构的 CLI 参数。隔离工作目录、设置、MCP 清单及环境变量；尤其移除可能把调用切到 API 的继承凭据。若该版本/运行方式无法满足订阅与官方支持条件，记录阻塞，不绕过认证、不使用反代或抓 Cookie，也不静默替换为 API。

CLI 协议、flags 与官方支持将变化，需 `--help` 和真实 smoke test 固定版本；版本升级必须重跑认证与权限测试。下列仅是官方输出模式参考，不是完整安全启动脚本：

```text
claude -p --output-format stream-json --verbose --include-partial-messages
```

输入从受控 stdin 传入；避免把敏感聊天正文放在进程命令行和全量日志。客户端表面 metadata/cost 不能单独证明最终扣费渠道，需结合官方登录状态与账户实际情况核验。[S8]

### 15.3 最小工具权限

周家明只得到 mariposa 业务工具与明确批准的其他能力，不因为运行在 Claude Code 里就能读 D 盘所有项目、密钥和数据卷。禁用/隔离不需要的 Bash、Edit、外部 filesystem 和未知 hooks。不能用 `dangerously-skip-permissions` 当作正常接入方案。

在实际 CLI 的工具暴露与设置机制上实施白名单；prompt 中“不要读文件”不算隔离。CC 进程不可直读 formal/workspace 数据库，开发工程助手和生活聊天进程使用不同工作目录与凭据。

### 15.4 会话与原文

每个 Web conversation 映射到明确 CC session ID；恢复使用指定 session，不用全局“最近会话”防止串线。相同会话一个生成租约，前端重连不发起第二次回答。多设备通过同一个后端看到事件序列。

用户消息先持久化，再调用 provider；流式 event 有递增序号和 turn_id。助手 visible text 保存为完成或 interrupted 消息；工具事件单独保存，30 条原文不计它们。不要把供应商私有内部推理日志抓取为业务聊天记录。

取消只影响本 turn/session，不能杀死其他会话；网络断开后按事件游标重放，不重新执行工具副作用。完成消息和工具结果可恢复；崩溃后未确定执行结果标 unknown 并对账，不自动多发一条星星。

## 16. 提醒、唤醒、媒体与外部服务

### 16.1 Scheduler 与自动唤醒

统一 Time Service，任务有唯一触发键、租约、截止时间、重试上限、冷却与静默时段。【默认】自动唤醒关闭，配置并真实验收后开启；读记忆不启动唤醒。

触发仅创建一个 CC 唤醒 turn，携带时间、相关计划与必要上下文；周家明可选择不发消息。提醒到点的程序通知与他的自然语言回复必须区分来源。过期积压任务不得补发成几十条问候。

不承诺通过 mariposa 强制唤醒 Claude.ai Chat；GPT 工具人同样不因建立 MCP 变成常驻 agent。需要 provider/推送服务的地方如未配置，显示未配置，而非“已通知”。

### 16.2 媒体与表情

真实上传、hash 去重、MIME/大小/危险文件检查、访问授权、受控下载、消息引用、缺失对象处理。头像与姓名取后端真实数据，不硬编码“生/明”等假头像。表情搜索/发送均走同一能力；资源删除按实际引用及旧删除边界处理，不能因为删一条消息就删共享附件。

主模型通过 MCP 获取上传会话/签名引用，不把大音频/整文件 base64 塞进工具参数。照片/信件附件不能被未经允许的 worker 批量读取。

### 16.3 Moments 与群聊存档

mariposa 自身的朋友圈帖子、评论、反应使用自己的实体；扎西德勒群聊存档通过 provider 引用原服务。`kind=post` 与 `kind=group_archive` 分开，不能导入聊天片段后冒充周家明主动发布了朋友圈。AI 的发帖决策由周家明发起，工具人只可测试合成数据。

### 16.4 外部适配

每个 provider 有能力探测、鉴权、版本、健康状态、超时、幂等与错误映射。第一次连真实服务先只读核验 schema，不猜路由。不更改现有业务规则来迁就 mariposa。

- Superposition：星星写/读/申请/回应等按照现有 API/MCP 实际清单接入，所有权、拆阅与足迹由原服务负责。
- Siren：语音发送与实时通话都保留。通话通过业务工具创建短期 session，Web 媒体流直连 Siren；MCP 只传控制和引用，不搬实时 PCM。
- 扎西德勒：好友、真实头像、群聊发送、历史/存档、个人主页引用；权限与人机绑定归原服务。
- 一起听歌：`ListeningProvider` 预留房间、播放状态、队列和同步事件；不承诺第三方音乐授权/曲库功能。未选供应商时 capability 标 reserved/unavailable。

下游不支持幂等键时，发出请求后超时应标 `OUTCOME_UNKNOWN` 并查询实际状态，不能对不可撤销社交写入盲重试。两个入口共享同一调用记录。

## 17. Capability / MCP / HTTP 契约

### 17.1 一份注册表，三个适配器

所有用户可用业务动作在 Registry 中定义：canonical_name、输入输出 schema、actor/scope、写入/只读标记、幂等和版本要求、handler、审计分类、provider 状态、对应测试。

HTTP、Claude Chat MCP、CC 调用同一个领域 handler。维护 MCP 只暴露 workspace 与经授权的 maintenance read，不是另一个后端。注册表可生成工具清单、OpenAPI/HTTP 适配与 UI 能力清单，禁止三份各写各的业务。

完整能力覆盖不意味着每次把全部工具schema灌入模型上下文。按实际客户端支持的工具发现/模块化配置组织清单；不支持按需发现时使用清晰的模块连接与相同主体绑定。所有已授权业务仍有可达的MCP路径，不能为了省token悄悄删除功能，也不能假定客户端支持尚未验证的动态加载。

建议远程路径 `/mcp`（周家明业务 profile）和 `/mcp/maintenance`（工具人 profile），**路径不赋予角色**；每条请求按 token binding 决定实际权限。避免 MCP session ID 被误当成登录令牌。优先实现经固定版本测试的 Streamable HTTP，必要兼容旧 SSE adapter；两者不是业务复制。[S3、S9]

工具名为内部 dot namespace；如某宿主不接受点号，可映射到 `mariposa_memory_search` 等 transport name，保留唯一 canonical mapping。不能为了减少工具数提供可以绕过所有授权的万能 exec/sql/shell。

### 17.2 公共请求/响应

```json
{
  "contract_version": "1.0",
  "capability": "memory.forgetting.decide",
  "arguments": {
    "proposal_id": "proposal_fixture_01",
    "proposal_revision": 1,
    "proposal_hash": "<sha256>",
    "expected_memory_version": 3,
    "decision": "approve"
  },
  "idempotency_key": "<stable-client-generated-key>"
}
```

这里没有用户可填写的 actor；可信执行上下文由服务器附加。HTTP 可以从 `Idempotency-Key` / `If-Match` 解析对应字段，MCP 在 schema 中显式传；相同语义不维护两套判断。

成功或错误统一包含：`ok`、`data` 或 `error`、`request_id`、`resource_version`（适用时）、`warnings`、`degraded`、分页字段。时间统一 ISO 格式，null 代表未知，不用空字符串伪造日期。

MCP 结果同时返回结构化数据及简短可读说明；业务错误通过 MCP 规范的 tool error 路径表达，不能每个错误都包成成功字符串。readOnly/destructive/idempotent hints 根据实际动作填，提示字段不是服务器权限保障。[S10]

### 17.4 必须单独固定 schema 的核心工具

- `memory.hold`：text、事件日期/范围及置信、why_remember、tags/emotions、raw_refs 或 pending、去重来源；返回正式 memory_id/version。
- `memory.search`：query、filters(date/tags/whose/state)、keyword/semantic/hybrid、cursor、limit；返回 matched_by/projection_kind/version/summary_or_text；无 `include_old_body` 默认后门。

- `workspace.proposals.submit`：proposal ID/revision/hash/base_version；提交后不修改该版本。

- `memory.restore`：memory ID、expected_current_version、target_history_version；默认回到最近压缩前版本；需验证原版本属于同一桶。

## 19. 事件、幂等与审计

### 19.1 事件信封

```json
{
  "event_id": "evt_fixture_01",
  "event_type": "memory.forgotten",
  "event_version": 1,
  "occurred_at": "2026-09-21T00:00:00Z",
  "resource_id": "mem_fixture_01",
  "resource_version": 4,
  "actor_principal": "jiaming",
  "initiated_by": "worker",
  "executor_kind": "system",
  "entry_source": "claude_chat",
  "correlation_id": "corr_fixture_01",
  "payload": {
    "proposal_id": "proposal_fixture_01",
    "representation": "forgotten_summary",
    "reversible": true
  }
}
```

原事件发生时间与动作执行时间分开；此处 `occurred_at` 是该业务事件执行时间，不拿来改 memory_date。事件不携带完整敏感正文、锁信内容、凭据；消费者要读取资源时重新鉴权。

必须事件：memory.created/updated/forgotten/restored、workspace.proposal.submitted/resolved、quote.semantic_corrected/withdrawn、memory.emotion.changed、plan.changed、raw.import.completed、calendar.sources.changed、home.updated、chat.turn.completed/interrupted、contact.observed、reminder.due、wakeup.requested/finished。

### 19.2 Outbox

正式写入与 outbox 同一事务；消费者以 event_id 去重，失败有次数/退避/死信状态。embedding、日历缓存失效、工作区回填可异步；正文/检索投影的权限变更不可依赖慢事件才生效。

默认“至少一次投递 + 幂等消费”，不宣称跨外部服务 exactly-once。动作发生但未收到响应的窗口靠记录、查询与对账处理。

### 19.3 审计覆盖

保存谁、哪个授权绑定、哪个入口、什么操作、哪个版本、结果、何时；不把内容作者和执行程序混为一谈。所有 approval/restore/绑定撤回/角色修改有记录。扫描日志可记录数量/hash/规则版本，不复制全部私有正文。

审计日志是操作记录，不参与默认记忆召回；不能变成另一个绕过遗忘规则的“隐藏全文记忆库”。也不能把工具访问时间并进 last_contact 或 last_reengaged。

## 20. 迁移、备份与回退

完整步骤见 `03_迁移与切换手册.md`，这里是必须满足的接口与验收条件。

### 20.1 四个隔离区

旧生产仍唯一写入 → 经允许取得一致性快照 → 新系统的迁移 staging → 验收后的新正式实例。GLM 日常开发只使用合成数据；真实快照仅在受控迁移执行中处理，不把整个真实库发给模型“分析”。

源代码只读盘点、复制源码到新项目与对生产数据做迁移是不同权限。当前写文档/开发授权不包含停服务、读真实锁信、改 Tunnel、切换主域或覆盖数据卷。

### 20.2 数据清单

迁移：原 Hold 正文、why_remember、日期/置信、meaning 各层与旧版、自定义/反向/断开关联、保护状态、plan 与 weight、原文与 detached binding、I/self、letters/锁、日记、她的话、媒体、旧删除/归档审批状态。旧审计/账本作为只读历史归档保留，不编造成新操作。

dream 运行机制不迁；历史文件如何保留写明为 legacy archive，不让新运行时消费或继续执行见证。旧草稿迁入 workspace，不得当成正式记忆。未识别字段放受限 legacy extension 并报告，不静默丢。

### 20.3 核对维度

不仅 count，还要逐项 ID 映射、正文 hash、附件 hash、日期、lock metadata、关联端点、所有权、状态、导入幂等。存在不能迁移项要列 ID/原因/影响；未完成核对的正式数据不能被“总数差不多”放行。

旧 ID 能保留就保留；必须改 ID 时 `migration_id_map` 持久化且所有引用可追踪。映射不得依赖模型文本匹配。旧长期被隐藏的正文不在重建时自动进入搜索。

### 20.4 备份

备份应包含正式库一致性快照、独立工作区一致性快照及交接 checkpoint、对象文件清单、schema/版本、校验 hash；密钥单独保管。SQLite 正在 WAL 写入时，不以简单复制一个 `.sqlite3` 文件代替一致性备份。[S6]

恢复演练必须证明事务/索引可重建、工作区提交不会重复应用、锁信不泄露、正在运行的 provider 动作不会重放。开发模型没有自动生产备份/恢复权限；脚本执行由受控管理流程发起。

### 20.5 切换与回退

获准后才停止旧写入并记下 cutover watermark；迁移最后变化，核验后切新入口。旧库保留只读。若新库尚无新写入，可回旧只读基准；若已产生新记录，必须先保全新增量并有实际增量回迁/对账方案，不能丢掉新记忆直接切回。

不做长期双写，不让新旧自动同步互相覆盖。外部项目数据库和隧道保持原状，除非另有明确批准。

## 22. GLM 的分阶段执行顺序

### Phase 0 · 现场只读盘点与契约固定

读取两个已知本地 Ombre 路径的 git/配置/部署信息，识别真实生产容器与数据卷，不默认 main2.5 或 dev 必然是运行源。输出 `docs/00_local_baseline.md`、`legacy_behavior_matrix.md`、`reuse_map.md`、`platform_preflight.md`；每项附路径/commit/测试证据，隐藏密钥与锁信正文。

核验 CC 的实际运行方式、订阅认证、官方 CLI 参数；MCP 两宿主接入条件；本机新端口/运行时。记录阻塞不猜测。固定正式/工作区 schema、核心 JSON schemas、版本与依赖锁。

**出口：** 明确哪些代码继承、哪些重建；不能将上游行为当本地事实。生产服务未改。

### Phase 1 · 身份与数据底座

搭建项目、独立库、migrations、权限绑定、统一 registry、审计/outbox、mock fixtures、doctor/start/stop。完成最小 Web 登录与 health，所有私有接口默认鉴权。开发用 synthetic 数据，不等真实库迁移才能测试。

**出口：** GPT maintenance token 无法写正式记忆/审批；CC/Claude Chat 同主体；工作区与正式库确实分开。

### Phase 2 · 第一条完整闭环：遗忘

写正式测试桶 → workspace 草稿 → 提交 → 乔生/周家明审批 → 摘要索引切换 → 搜索命中/不命中 → 恢复。实现 FTS、投影、语义 provider/降级、跨库中断恢复、幂等、版本冲突与迟到向量测试。

**出口：** 对照 `T-FOR-*` / `T-RET-*` 全部过，不允许先写十几个页面再补这条链。

### Phase 3 · 原文、Hold、日期、关联和独立内容

原文导入/归档/去重、先 Hold 后绑定、日期置信、情绪主语、quotes 语义核对、Home/Self/Diary/meaning。后台所有草稿和不确定校验只入 workspace。

**出口：** 不逐字也能保留复述；明确语义冲突才修正；原文不被改写；同源不重复形成正式记忆。

### Phase 4 · 计划、日历、bootstrap 与时间证据

实施两套开窗规则、分页、snapshot 失效、真实联系与程序活动分离、日历源聚合、计划状态过滤。默认关闭情绪额外检索但接口可测。

**出口：** Claude Chat 30条/3天/相关计划，CC 无自动 raw；旧桶晚导入不进近三天；日历能显示遗忘摘要。

### Phase 5 · 沿用规则与迁移演练

移植核验后的信件/删除行为，先特征测试再适配。运行合成/脱敏 fixture 迁移、导入幂等、备份恢复、锁信不可读和旧状态保留测试。获准取得真实快照后做 dry-run 核对，不切换。

**出口：** 迁移报告无静默缺失；真实数据未核验则标明未核验，不能写生产迁移完成。

### Phase 6 · 真实 MCP / CC 聊天接入

完成远程 MCP OAuth 与主体映射、GPT Chat maintenance、Claude Chat 主体连接、CC 明确 session 流式聊天/工具调用/取消/恢复、原文归档。真实平台 smoke tests 和 mock tests 分开记录。

**出口：** 实际客户端成功运行指定只读/写草稿/主体写入/拒绝越权用例。凭据或平台能力缺失则该项 blocked；不以 SDK mock 代替。

### Phase 7 · 生活功能与外部 provider

完成媒体/表情/朋友圈/提醒/自动唤醒的真 API 与 UI；逐个接 Siren/Superposition/扎西德勒，先只读契约检查后写入测试。没有真实服务时标功能未联调，不制造成功事件。一起听歌和情绪算法维持已声明预留，不假实现。

**出口：** 所有已纳入第一版业务在 Web 与允许主体的 MCP 都可达；未完成项逐项列出。

### Phase 8 · 全量验收与发布候选

跑单元、契约、集成、E2E、并发、崩溃恢复、权限、迁移、备份恢复；交付清单/差异/截图/命令/commit。验证无密钥/真实私有内容入 git，无跨项目修改。产出候选构建，不自动发布。

**出口：** 完成不等于“有多少测试绿了”；以 `02_验收用例.md` 的关键场景和真实联调状态为准。

### Phase 9 · 经单独批准的生产切换

仅在乔生明确同意后执行。按迁移手册暂停旧写入、末次增量、核验、切入口、观察、回退。不得把当前“写工程文档/开始开发”解释为这个批准。

## 23. 测试与交付标准

### 23.1 必需测试层

- Unit：权限、日期窗口、计划过滤、状态流、投影选择、幂等、语义校对分类。
- Contract：同一能力 Web/MCP/CC 输入输出与权限一致；平台 OAuth/工具 schema 符合实测版本。
- Integration：正式库+工作区+索引+outbox，故障点注入、并发、重启恢复。
- E2E：真实页面完成创建/检索/审批/恢复/日历跳转/聊天；按钮不是摆设。
- Migration：ID/hash/锁/日期/relations/重复导入/未识别字段/数据回退。
- Live：CC 订阅实测、两个平台 MCP、三外部服务；与 mock 报告严格分开。

`02_验收用例.md` 是最低验收清单，GLM 需将其映射到测试文件/测试名、执行命令与结果。文件本身是测试规格，不是已执行证明。

### 23.2 必须实现的工程命令目标

以下是交付要求，**当前文档包没有附带可运行 mariposa 代码**。GLM 在项目中实现或给出明确等价命令：

```text
scripts/doctor.ps1                         # 运行时、端口、配置、权限与数据路径检查
scripts/start-dev.ps1                      # 不启动生产 provider 副作用
scripts/stop-dev.ps1                       # 只停本项目进程
python -m mariposa.migration inventory     # 只读清单，显式 source 参数
python -m mariposa.migration dry-run       # 只处理已允许的副本
python -m mariposa.migration verify        # hash/关系/锁/日期/丢失报告
python -m mariposa.storage backup          # 一致性备份
python -m mariposa.storage restore --verify-only
pytest tests/unit tests/contract tests/integration
npm --prefix apps/web run build
npm --prefix apps/web run test:e2e
```

任何迁移/恢复命令默认 dry-run 或拒绝覆盖非空目标；真实 apply/cutover 必须独立明确授权参数与检查。stop 脚本不得按模糊进程名杀死所有 Python/Node/cloudflared。

### 23.3 每阶段报告格式

阶段、commit、改动文件、schema 版本、完成能力、测试命令与摘要、真实联调/模拟区分、未完成项、阻塞、未改变的生产边界、下一阶段工作。写入 `docs/PROGRESS.md` 与 `docs/NEXT.md`，中断后可接续，不依赖模型聊天记忆。

只读审计先行；不要求每个小阶段都问用户“继续吗”。可持续推进已授权的隔离开发；涉及真实私有数据、外部副作用、计费方式改变或生产切换时保持明确边界。

### 23.4 完成判据

已完成：代码 + 实际路由 + 权限 + 数据持久化 + 测试 + 真实必要依赖验收。`reserved` 是明确后续范围；`blocked` 是尚未具备条件；两者不能混入“完成率100%”。

不能以删除失败用例、放宽断言、固定 mock 返回、关掉权限、关掉语义搜索等方式获取全绿。发现文档相互冲突时按 §0.2；涉及未授权的价值/角色变更则记录并采用不产生副作用的默认，而不是自行改产品语义。

## 24. 给实现者的最终指令

先保护旧家，再搭新家。mariposa 要继承已有内容和经过核验的行为，不继承已经被替换的旧流程。

第一条必须做通的能力不是漂亮的首页，而是：**工具人的候选永远不是正式记忆；批准的摘要真正替换检索依据；旧笔迹仍可被明确找回。**

记忆归同一个周家明；乔生、周家明、工具人与程序的权限必须由代码明确区分。模型的口头声明不能改变这些边界。整个系统每一处读取都应能回答：读的是哪一份、哪个版本、为什么能看到、依据什么搜到。

本文件与配套清单是实施规格，不证明任何源代码已修改、平台已接通、数据已迁移或测试已通过。

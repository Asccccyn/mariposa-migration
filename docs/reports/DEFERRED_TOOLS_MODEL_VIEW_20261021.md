# 按需工具定义与记忆模型视图（2026-10-21）

## 结果

新窗口默认使用tool_catalog/tool_define/tool_invoke三个固定入口；工具完整schema不会预先塞进请求。目录仅有名称和简短用途。需要使用时读取某一工具定义，得到definition_id；只有这份定义已经进入本窗口、本房间实际发送的请求，才能通过tool_invoke调用。未加载、伪造句柄、跨房间、同批define后立刻invoke均拒绝。定义已在当前请求可见时，重复define只返回引用，不重复schema。

统一调用入口继续使用原来的参数校验、工具白名单、主体权限、操作幂等、回执核验、停止门和副作用记账。context_review_complete通过统一入口调用时仍排在本批写入之后。首次使用会多一次定义查询；不知道工具名时还需查目录。因此输入体积减少不等于任何场景的总费用必然下降。

## 旧窗口与缓存

新增迁移32：window_toolsets持久保存每窗原始wire工具集和内部目录。已有窗口优先从最后实际发送的payload_json恢复精确工具定义，包括空工具集；不能恢复则阻断，不擅自换掉缓存前缀。新窗口才默认按需模式。runtime.tool_schema_mode=legacy是兼容选项，但不会改变已经冻结的窗口。

读取定义只在tool结果尾部追加，不修改顶层tools；跨轮及重新读取持久快照时工具定义不增长。旧聊天、旧工具结果、已有缓存不清除或改写。本批未强制换窗。

## Mariposa JSON 瘦身

写记忆给模型的成功结果改为 {"saved":true,"memory_id":"..."}。operation_id、version、binding_ids、committed_at、quoted_messages不再进入聊天结果；后端仍验证完整收据并记录已核验的副作用。结果不明仍明确报错、不暗示安全重发。

Mariposa memory.hold、memory.open、memory.detail.read支持显式view=model。默认full保持旧API/后台合同；模型用的open和详情客户端主动选择model。hold的模型视图投影在原子写和完整幂等回执之后进行，同一operation_id切换full/model视图仍重放同一笔写入，不新增记忆。

模型详情移除快照ID、版本向量、同步/导入来源字段、重复正文编码、审计时间戳与指令权限包装。保留完整正文、标题/分类/心情、双方话语、后来的回忆、留存与关系、来源原文；保留有业务意义的日期和用于定点操作的最小ID。明确打开票据、分页游标、分片范围、缺失状态和实际内容变更提示不能删，否则会破坏确认、续读或一致性。

后台数据库、审计、来源绑定与全量owner视图未删字段，未生成摘要、未改写正文。

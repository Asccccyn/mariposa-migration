# JEV IncompleteRead 原因与修复 · 2026-10-21

## 已确认的协议原因

真实响应为 HTTP 200、Transfer-Encoding: chunked、无 Content-Length。异常链是 `_read_chunked → _get_chunk_left → _read_next_chunk_size`，最后对空字节行解析16进制块长度时报 ValueError。也就是正文数据块已经读完，下一块长度（包括应有的最终零长度块）却遇到 EOF。

保留正文是可解析的单个 JSON，包含 model、answers、usage；此次样例的所有问题答案都在其中。不是语义低分、不是总预算超时。仅凭客户端无法区分是 JEV 服务端还是中间代理没有正常完成分块收尾，不能把责任归到某一方。

## 修复方式

仅在 HTTP 200、application/json、chunked、无 Content-Length、无压缩，且异常链严格匹配“完整数据块后读取下一块长度遇到空行EOF”时尝试恢复。缺数据字节、缺块尾CRLF、非法块长度等其他错误不恢复。

恢复必须全部满足：
- 最多256KiB，严格UTF-8，恰好一个完整JSON，无多余文档；拒绝所有层级重复键、NaN/Infinity。
- 顶层恰有 model/answers/usage，model非空。
- answers 的键集合与本次请求 questions 完全相等，无缺项或额外问题。
- 每题均为本适配器支持的 noul；答案仅含type/noul，数值有限且在[0,1]内，拒绝布尔或字符串伪数字。
- usage的input_tokens/output_tokens存在且为非负整数。
- 恢复时仍未超过绝对deadline。

恢复的是已收到的应用响应，不重新发送付费请求，不补造任何答案。之后仍经过原有模型版本、分数、事实、权限与缓存逻辑。
不能满足这些条件时继续 fail closed。日志只记录恢复字节数和答案个数，不记录正文、问题键或凭据。

## 缓存影响

本次没有修改缓存键、缓存规则、阈值、提示词、上下文轨迹或窗口；没有清缓存。
有效恢复结果走原有缓存写入，下一次相同判断可命中；非法残片不写缓存。没有使用真实 OR API key。

## 验证

离线100项回归通过，其中30项为本次新增；使用真实Python HTTPResponse分块解析器模拟缺最终块，而非手工伪造一个异常。覆盖正常响应、不完整正文、错误块长度、缺答案、额外答案、重复JSON键、非法数值、超时、不重发及缓存污染防护。

真实JEV：对原9个失败样例各测两轮，18次场景、30次HTTP请求。观察到2次真实缺结束块异常，2次均通过严格验证恢复，并最终交付且check=true。没有传输blocked，也没有为恢复增加请求。
12次正例运行：11次交付，1次正常语义弃权（h-p5第二轮同事件0.76，低于当前交付0.80；不是传输失败）。6次反例运行均正常弃权，零错误交付。
此为有限真实样本，不是服务永不失败或语义召回率100%的保证。
